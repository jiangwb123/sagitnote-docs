Quick answer: the most effective visual feedback for an AI coding assistant pairs a visual mark (what looks wrong) with a machine-readable anchor (which element, as an XPath or CSS selector) and a precise instruction (what to change). A screenshot alone makes the model guess the element; prose alone is ambiguous. The workflow below shows how to produce all three at once — free — with Sagitnote's Generate Modification Prompts.
The Problem

Why "fix the button on the right" wastes a round trip

Anyone who reviews UI with an AI pair-programmer knows the loop: you look at the rendered page, something is off, you type a description, the model guesses, ships a change, and — half the time — fixed the wrong thing. Repeat until you give up and edit it yourself.

The failure isn't the model's intelligence; it's the input. Human eyes resolve "the button on the right" against the whole visual scene instantly. The model only has your words and the codebase — and if the page has four similarly-named buttons across three components, your sentence is genuinely ambiguous.

What resolves the ambiguity is an address: point at the exact element in the DOM, and suddenly "make this smaller" has exactly one referent.

Three Approaches

From worst to best

1. Screenshot + prose (the default)

Paste a screenshot and write "the heading overlaps the card below it". Works, because modern models read images well — but the model must find the element in code by description alone. Every ambiguity costs a round trip.

2. Manual anchors from DevTools

Open DevTools, inspect the element, copy its CSS selector or XPath, paste that with your instruction. Precise — and tedious enough that nobody does it for more than one or two issues per page.

3. Mark visually, export anchors automatically

This is the sweet spot: you point at the page the way your eyes already do — drawing on it — and software translates every mark into a selector-anchored instruction. That's exactly what Sagitnote's Generate Modification Prompts does; the rest of this page is that workflow.

The Workflow

Annotate the page, get a fix-ready prompt

With Sagitnote (free) — about a minute per review round

  1. Mark the issues on the live page

    Open the page in Chrome or Edge, enable Sagitnote, and mark each problem: arrow at the misaligned element, box around the broken region, highlight on the bad copy. In each note, write the fix you want — that text becomes the instruction.

  2. Generate the Modification Prompt

    Open the annotation panel's More (⋯) menu → Generate Modification Prompts. Sagitnote aggregates every mark on the page into one structured Markdown document, sorted top to bottom.

  3. Copy or download

    One click copies the whole prompt to the clipboard; another downloads it as sagitnote-modification-prompt-YYYY-MM-DD.md.

  4. Paste into your assistant

    Works with Claude Code, Cursor, GitHub Copilot, Windsurf, Cline, or any chat assistant. For agentic setups, the XPath anchors are directly consumable: an agent with browser access (e.g. via Chrome DevTools MCP) can locate each anchor, verify it by the element text, and edit the surrounding component.

  5. Review, iterate

    After the fix lands, reload and mark whatever's still off — each round produces a fresh prompt. Because your marks live on the page, the full issue list stays visible while you work through it.

Craft

Five habits that make AI feedback land

  • 1. One issue per annotation. Bundled instructions ("fix spacing, rewrite copy, and make it dark mode") get half-done. Separate marks produce separate, checkable instructions.
  • 2. Describe the desired end state, not just the flaw. "Reduce to 14px so the row fits one line" beats "looks cramped".
  • 3. Use the arrow for position, note for intent. The arrow gives the anchor; your note gives the reason and the fix. Together they're unambiguous.
  • 4. Verify with the element text. The prompt includes the element's text so the assistant can confirm it found the right node before editing — encourage it to check.
  • 5. Keep rounds small. Ten anchored fixes per prompt is plenty; models execute short lists far more reliably than long ones.
FAQ

Questions, answered

Why isn't a screenshot alone enough feedback for an AI assistant?

A screenshot shows the problem but not its address. The model has to guess which element you mean ('the button on the right' — of the eleven buttons on the page?), then search the DOM for a match. Pairing the visual mark with a machine-readable anchor (an XPath or CSS selector) plus the element's actual text removes that guesswork: the assistant verifies the position from the selector and the element text, then edits the right component.

What is an XPath or CSS selector anchor?

It's the machine-readable address of one element in the DOM — for example /html/body/main/section[2]/div/h2 points at a specific heading. Assistants with browser or DevTools access (for example an agent using Chrome DevTools MCP) can jump straight to that element, confirm it by its text, and inspect the surrounding code before editing.

Which AI coding assistants does this work with?

Any chat-based assistant — Claude Code, Cursor, GitHub Copilot, Windsurf, Cline, or a plain chat with Claude, ChatGPT, or Gemini — because the output is ordinary Markdown you paste in. It works best with agentic setups that can read the XPath anchors directly, such as agents wired to the page through Chrome DevTools MCP.

Does it work on any website?

It works wherever the extension can annotate: regular pages, SPAs with client-side routing, pages with iframes and Shadow DOM, and math-rendering sites. Browser-internal pages like chrome:// and edge:// can't be annotated.
